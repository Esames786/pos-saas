Offline Edge Architecture

One cashier screen, two places to run it. The Cloud stays the financial truth; the Branch Server is a warm standby that becomes the branch's writer only after a supervised takeover, and hands everything back exactly once.

1. The system

The same Blade renders on both sides. The only switch is the runtime adapter (window.POS_RUNTIME): on the Cloud it maps to /pos and the Online endpoints; on the appliance it maps every one of them to an /edge/local/pos/* twin and turns capabilities on or off.

2. Online mode and offline mode

The appliance is never a second writer. In STANDBY it only reads from the Cloud and refuses every mutation; after a supervised takeover it is the writer for its own branch; on handback the Cloud takes over again and the outbox is applied exactly once.

Online mode (normal day)

  • Cashiers use the Online POS at /pos on bingoopos.com; prints go through the shop's print agent.
  • The appliance heartbeats, pulls menu, prices, users, roles, permissions, printers, tables, customers and the alias book, and keeps the returnable-sale mirror and backups current.
  • The Cloud advertises what the appliance may do offline (for example customer_create); the appliance stores it with the heartbeat ACK.

Offline mode (after takeover)

  • Cashiers open https://<host>.local:8443/edge/local/pos: the identical screen, status slot reads LOCAL MODE.
  • Every sale becomes an outbox envelope; manager approvals need an eligible approver who is not the requester; add-customer creates a canonical customer_uuid locally (Phase 4).
  • Finance posting (daily closing, journals) stays on the Cloud; non-cash tenders and e-mail are refused with a hint, never faked.

3. How the home lab is wired, and where the FakePrinter sits

Everything runs on the owner's laptop plus a second laptop for cashier acceptance. The LAB Cloud plays bingoopos.com; the appliance is a real installed package; the FakePrinter stands in for the LAN printers.
