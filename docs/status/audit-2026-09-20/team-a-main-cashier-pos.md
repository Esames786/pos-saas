## (4) Validation rule diffs
**SOC@validateSale (SOC:821-902 + :110-115) vs ELPC@storeSale (ELPC:468-495)**
- Online REQUIRES `kot_print_intent` + `receipt_print_intent` on tenant.pos.store; Edge has no such fields.
- Online: `branch_id required exists`, `terminal_id exists`, `held_sale_id exists`, `restaurant_table_session_id exists`, `create_separate_order`, `order_source in:pos,manual`, `client_uuid nullable`, `customer_email`, `tip_amount`, `notes`, `void_items.*`, `lines.*.{sales_order_line_id, client_line_key, parent_client_line_key, line_kind in:, line_name, unit_price, discount_amount, tax_amount, modifiers string}`, `payments.*.{bank_name, account_no, transaction_ref, card_last_four, cheque_no, cheque_date, notes}` — **all absent on Edge** (Edge derives branch/terminal from binding/session; `client_uuid REQUIRED` on Edge).
- Types: Online uses `exists:` for customer/channel/rider/product/variant/combo/approval/waiter; Edge uses bare `integer` and relies on service lookups (customer only checked for delivery ELPS:1590; product `findOrFail` → 422 via RuntimeException; waiter/rider/channel active checks in ELPS).
- Quantities: Online `lines.*.quantity nullable min:0.001` + assertNoZeroQuantityLines; Edge `required numeric gt:0`. Payments: Online `amount nullable min:0.01` (empties filtered); Edge `required gt:0`, exactly ONE cash row (ELPS:404-406).
- `order_type`: Online `in:` list; Edge `string` → service refuses dine_in for Direct Pay (ELPS:63 OFFLINE_ORDER_TYPES excludes dine_in; T-Http:127). `discount_type`: Online required in:; Edge nullable → service vocabulary check. Edge extra: line `discount_amount != 0` → 422 (ELPS:354-358); percent ≤ 100 enforced server-side (Online client-side only).
- Delivery: Online requires rider for own channel (SOC:938-942); Edge rider optional (ELPS:1594). Both: channel required, aggregator customer optional, locked charge.
**HSC@store (HSC:264-306) vs ELPC@storeHeldSale (ELPC:606-638)**
- Online requires `branch_id`, `discount_type required`; `lines.*.product_id required_with quantity exists`, `customer_name max:200`, `customer_email`, `restaurant_table_id exists`, `create_separate_order`, `void_items.*.product_name`, `lines.*.{client_line_key,parent_client_line_key,line_kind,line_name,unit_price,modifiers string}`; Edge lacks these, uses `required_without:lines.*.combo_id`, `customer_name max:190`, `lines.*.modifiers array`.
- Edge accepts `notes max:1000` (ELPC:610) but **never persists it** — the held-sale insert has no `notes` key (ELPS:747-788; only openTableSession ELPS:655 and split ELPS:1318 store notes).
- Edge `void_items.*.reason_id integer` vs Online `exists:void_reasons,id`; Edge `void_items.*.old_line_id required_with:void_items` vs Online nullable.
- Edge enforces one open check per table session with a locking read (ELPS:735-737, RuntimeException 422) — Online returns `TABLE_HAS_OPEN_ORDERS` with choices.
