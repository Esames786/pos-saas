## Financial rule differences (consolidated)
1. Tender: Online any active method type + optional card/bank reference; Edge exactly one CASH payment (`ELPS:402-419`) — bank_transfer/cheque/other tender not covered by the accepted contract (only card/provider is).
2. Refunds: Online cash/bank_transfer/card/other with per-method shift buckets; Edge cash only (`config/edge.php:93`), refund leaves the sale's own open shift else current terminal's (`ELRS:208-216`); bank/other refund not covered by the contract.
3. Shift close: shared `ShiftService::closeShift` (zero-drawer, blank-count refusal) on both; Edge has NO denomination count (no CashCountLine), NO CASH-SHORTAGE draft expense voucher, NO Close Branch / Daily Closing; Edge shift totals reach the Cloud only implicitly via sale envelopes (NOT_VERIFIED).
4. Approvals: same creator/consume semantics (10-min expiry, single-use, requester + payload binding); identity differs — Online manager PIN (any active pin), Edge manager's own credential + `tenant.pos.void-kot-item`. No amount thresholds on either side; branch mode flags only.
5. Supplier payment: both require Cash/Bank account; Edge additionally enforces fresh projection, active COA-mapped cash/bank, bill available cap, no negative payable; card to supplier refused offline (accepted).
6. Journal: Edge enforces debit-XOR-credit, AP-line-names-active-supplier, supplier only on AP, cash/bank must map to the posted COA account, balanced, no negative payable; Online delegates most to `ManualJournalService` (not read). No offline reversal.
7. Purchase return: Edge posts immediately (no draft), GRN mandatory, unit cost from receipt, over-return checked against received − Cloud returned − pending local; both permissions (store+post) needed to post.
8. Permission gaps in Edge: shift open/close unguarded (Online `tenant.shifts.store/close`); Returns/Quick Report/Shift buttons rendered regardless of permission (server still 403s); return search ignores UserDataScope; `GET /edge/local/pos/shift` returns amounts unmasked.
